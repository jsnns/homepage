Look at what an LLM spends its weights on. A huge fraction of the parameters in a model like GPT-4 go toward memorizing facts—a static snapshot of the world as of the last training run. The model is, in large part, an enormous and very expensive fact database that happens to also reason.

That raises the question this post is actually about: **are data and reasoning separable?** Does it make sense for the weights to encode all the precedents? Is that remotely the most efficient use of them?

The problem with a learned representation of the world's data is twofold. It goes stale the moment training ends—a model trained through 2021 knows nothing about 2023. And it's capped by capacity: there is more information in the world than any set of weights can hold, and the fastest-updating information is exactly what the weights hold worst.

## The proposal

So: could you train an LLM *with tools* such that it never memorizes facts at all—it just learns how to access them?

This is not retrieval bolted on at inference time. Retrieval-augmented generation grafts a search step onto a model that already spent its capacity memorizing. The interesting version happens at training time: the model learns from the start that facts live outside itself.

Concretely:

1. Reserve part of the context window as a live data feed.
2. Give the model special tokens—`[START_QUERY]`...`[END_QUERY]`—to emit a retrieval query mid-generation; an external system runs it against the corpus and injects results back between `[START_RESULT]` and `[END_RESULT]`.
3. Train the model end-to-end with this loop in place, so it learns when to query, how to phrase queries, and how to integrate what comes back—instead of learning the facts themselves.

If facts are always one query away during training, there's no gradient pressure to memorize them. The weights get spent on the thing only weights can do: reasoning. And you get the other properties for free—knowledge that updates by updating the corpus, not retraining, and models you can specialize post-training just by changing what data they can reach.

## What's hard about it

Retrieval has to be fast enough to sit inside the generation loop. Coherence is tricky when the context window keeps changing underneath the model. And teaching a model to write good queries is its own learning problem—probably some mix of supervised examples and reinforcement.

But the bet is simple: a model that learns how to find things should beat a same-sized model that memorized things, on everything except closed-book trivia. If data and reasoning are separable, the weights we currently spend on being an encyclopedia are the cheapest capability gain available.
